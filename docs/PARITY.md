# 功能对齐说明

简体中文 | [English](PARITY.en.md)

基线是同作者早期 Slint 版 mqttc v0.1.1（仅本地保留，不随仓库分发）。egui 与 Iced 版
目标为**完整对齐**，GPUI 版为**核心功能对齐**，差异逐条列在下面。所有界面共用
`mqttc-core`，因此配置格式、协议行为、日志上限、自动回复与定时发布逻辑完全一致。

正式 Release 只提供 Iced 版（打包为 `mqttc`）；egui / gpui 需从源码构建。

## 2. egui / Iced 与早期 Slint 版的差异

两者功能完整，差异只在实现层面：

- **日志渲染**：早期 Slint 版用 Slint 列表；egui 用 `ScrollArea::show_rows` 只布局可见行，
  Iced 只布局最新 80 条，上滚时冻结当前页并可“显示更早”逐页加载、出现新消息时可“回到最新”。
  气泡宽度按内容自适应（上限 85%）。滚动条样式不同（egui 细滚动条、Iced `Scrollbar::new()`）。
- **字体**：不打包 CJK 字体，使用系统字体回退（egui: fontique；Iced: cosmic-text，默认族按平台选
  Microsoft YaHei UI / PingFang SC）。早期 Slint 版打包的字形文件因此体积更大。
- **标题栏**：egui 使用原生标题栏；Iced 使用无边框窗口 + 自绘标题栏（品牌、最小化 / 最大化 /
  关闭、置顶图钉、双击最大化、四边缩放手柄），主题同时作用于标题区。Windows 下最大化按显示器工作区
  取值，适配高 DPI。
- **界面个性化**：Iced 提供 27 色槽的自定义配色编辑器与 4 档全局字号；egui / GPUI 会读取并
  应用同一份 `custom_palette`，但没有编辑入口，字号固定为 1.0。
- **下拉框**：egui 用 `ComboBox`，Iced 用 `pick_list`，交互与参考的弹出菜单一致，但弹出动画/阴影由框架决定。
- **系统皮肤检测**：Windows 读注册表，默认每秒检查一次；macOS / Linux 调用 `defaults` / `gsettings`，
  结果缓存 30 秒。早期 Slint 版使用 Slint 自带的检测。
- **会话页补充**：Iced 的会话标题行显示当前连接的收 / 发计数并可清零，预设标签名为“预设回复”；
  egui / GPUI 不显示流量计数。三者共享同一份日志上限设置。
- **多行负载**：egui 与 Iced 均提供多行编辑框；Hex / Base64 的容错规则与早期版本一致。

## 3. GPUI 版差异（有意简化）

GPUI 0.2.2 只提供 div / 文本 / 列表等基础元素，没有控件库；为控制工期，做了如下取舍：

| 项 | GPUI 行为 | 原因 / 影响 |
|---|---|---|
| 发布负载 | 单行输入框（`TextInput`），非多行编辑器 | 会话页仍可编辑并发送任意文本；大量 JSON 编辑不便 |
| 预设 / 规则文本 | 只读展示，可新增 / 删除 / 启停 / 循环 QoS、格式、Retain、发送 | 文本编辑需要每个字段一套 IME 输入框，先用只读避免半成品；可在 egui / Iced / 早期 Slint 版编辑同一 `mqttc.json` 后回到 GPUI 生效 |
| 下拉选择 | 点击循环的 chip（`QoS 0 ▾` 点击 → `QoS 1`） | 无弹出层控件；选项均为 2–6 个，循环可接受 |
| 日志列表 | `uniform_list` 固定行高、单行省略号，按类型着色 | 无气泡布局；信息（时间/类型/topic/负载）与参考一致 |
| 窗口图标 | 无 | GPUI 0.2.2 未暴露设置窗口图标的 API |
| 中文输入 | 使用官方 example 移植的 `TextInput`，含 IME marked text、密码遮罩 | 需实测确认各平台输入法行为 |
| 多行 / 富文本 | 无 | 同上 |
| 自动重绘 | 连接中 / 定时发布开启时 100ms tick；系统皮肤空闲时 1s tick；否则无 tick | 降低空闲 CPU；egui 为事件唤醒，Iced 有活动时 100ms tick |

**共用部分**：连接、TLS、订阅、发布编码、自动回复、定时发布、200 条日志、导出、过滤、
皮肤色板、中英文切换、配置读写全部来自 `mqttc-core`，与 egui / Iced 行为一致。

## 4. 配置兼容性

四个程序读写同一份 `mqttc.json`（字段名、默认值、迁移逻辑由 `mqttc-core::config` 提供）：

- 早期 Slint 版保存的连接、预设、规则可直接被新程序加载；反之亦然。
- 旧版单连接配置自动迁移；`active_id` 失效时回退到第一条连接；预设/规则缺字段时补齐默认值。
- GPUI 只读的规则/预设文本在保存时原样保留，不会被清空。

## 5. 基准模式（新增能力）

早期 Slint 版没有命令行参数。三款新程序支持：

```text
--bench --bench-scenario s1|s2|s3|s4 --bench-quit-after <secs> --config <path>
```

用于无人值守的内存 / CPU 采样，输出 `FIRST_FRAME_MS`、`BENCH_SUMMARY`、`BENCH_QUIT`。
该模式只影响启动与退出，不改变正常交互路径。
